リベース：変更を統合する際に、履歴をきれいに整えるために使う

git rebase <ブランチ名>

ブランチの基点となるコミットを別のコミットに移動
その際履歴は直線状にきれいになる

流れ
移動させたいブランチからするところのブランチにリベース
リベースされたブランチに入り、ブランチをマージ

リベースとマージの違い
リベース
・新コミットはつくられない
・履歴が直線状
マージ
・新コミットが作られる
・履歴が枝分かれ

リベースでしてはいけないこと
→gitにpushしたコミットをリベースすること

既にpushしているコミットをリベースして再度pushはできない！
リモートとローカルのほうでコミット履歴の情報が違う
git側が情報を信用できなくなる

git push -f　は絶対NG

56
リベースとマージの使い分け
マージ：作業の履歴をすべて残したい人向け
・コンフリクトの修正が簡単

リベース：履歴をきれいにしたい人向け

リベースは各コミットごとにコンフリクトが起こる

※pushしたあと、コンフリクトしそうならマージ

pullにはマージ型とリベース型がある

プルのマージ型
git pull <リモート名> <ブランチ名> 

マージコミットが残る、マージした記録を残したい人向け

プルのリベース型

git pull --rebase <リモート名> <ブランチ名> 


マージコミットが残らない、git内容のみ取得したい人向け
プルをリベース型に設定
git config --global pull.rebase ture
マスターブランチのみで適応
git config --global branch.master.rebase ture

58
直前のコミットをやり直す
git ci --amend

複数のコミットをやり直す
git rebase -i <コミットID>
git rebase -i HEAD~3

-i = --interactive：対話的リベースやり取りしながら履歴を変更

コミットの指定方法
HEAD~　：～番目の親(未マージ)
HEAD^　：マージ後の～番目の親

１git rebase -iで対話的リベースモードに入る
２：修正したいコミットをedit→そこでコミットの適用が停止
３：git ci --amend
４：git rebase --continue
５：コミットの内容を適用
