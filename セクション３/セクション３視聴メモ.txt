Gitはファイルをスナップショットで記録

例：3つのファイルをバージョン１として保存
↓
3ファイルの内  
ファイルB→ファイルB1
ファイルC→ファイルC1
これをシートの差分ではなくシートのスナップショットとして　
バージョン2に保存


スナップショットとして保存することにより
ブランチをマーするときの速度を上げる

コミットが直前のコミットを記録しているので
コミットをたどることで以前の状態に戻せる

14
ローカルリポジトリからスナップショットを保存し
gitへアップロード（リモートリポジトリ）


リポジトリ：履歴データの置き場BD
ワークツリー：自身のPCの作業場、ファイルを変更する場
ステージ：コミット(スナップショットの記録)を準備する場
内容の変更を完了済みのファイル分だけを記録ステージに置くと、
置いた分がリポジトリに記録される

ローカルは３つのエリアに分かれている

ワークツリー→ステージ→リポジトリ

15
データの管理方法　データ構造

Gitのデータの持ち方
新しくファイルを保存する
１：ワークツリー→リポジトリにファイルの中身を圧縮したファイルを保存
※実際は文字列をハッシュ関数で暗号化した文字列がファイルになる

２：リポジトリ→ステージにインデックスにファイル名のマッピング情報を記載　git add

３：インデックスのファイル構成情報をもとにツリー１がリポジトリに作成し
コミット１(構成：ファイル名、作成者、日付、コミットメッセージ)が作られる　git commit

リポジトリには、圧縮ファイル、ツリー１、コミット１の３つのファイルが保存


16
新ファイルの追加分を保存する

１：ワークツリー→リポジトリにファイルの中身を圧縮したファイルを保存
※実際は文字列をハッシュ関数で暗号化した文字列がファイルになる

２：リポジトリ→ステージにインデックスに今までのフファイルのマッピング情報が
記載　git add

３：インデックスのファイル構成情報をもとにツリー２がリポジトリに作成し
コミット２(構成：ツリー２、親コミット１、作成者、日付、コミットメッセージ)が作られる　git commit
親コミットがあるのは変更履歴をたどれるように


ファイル内容を更新した場合

１：ワークツリー→リポジトリにファイルの中身を変更したものの圧縮ファイルを保存
※実際は文字列をハッシュ関数で暗号化した文字列がファイルになる

２：リポジトリ→ステージにインデックスに今までのフファイルのマッピング情報が
記載　git add

３：インデックスのファイル構成情報をもとにツリー３がリポジトリに作成し
コミット３(構成：ツリー３、親コミット２、作成者、日付、コミットメッセージ)が作られる　git commit
親コミットがあるのは変更履歴をたどれるように

まとめ
・リポジトリには、圧縮ファイル、ツリー１、コミット１の３つのファイルが保存
・コミットが親コミットを持つことで変更履歴をたどる
・Gitの本質はデータを圧縮して、スナップショットで保存
・Gitコマンドはデータ操作のコマンド

gitにプッシュ→リモートリポジトリにローカルの内容をアップすること

事前準備：リモートリポジトリを新規追加
originという名前でURLのリモートリポジトリに登録
git remote add origin <URL>

originはgitの慣用句

１：リモートリポジトリへ送信
git push <リモート名> <ブランチ名>
git push origin master


パーソナルアクセストークン
gitにpushする際にユーザー名とパーソナルアクセストークン(鍵)
を使ってアカウント認証する
次回以降git pushだけでプッシュできるようになる
